# Search visibility and SEO

**Reviewed:** 14 November 2026

## What the implementation covers

The six public pages have unique search titles, descriptions, canonical URLs, Open Graph tags and Twitter cards. `src/config/seo.ts` is the source for page metadata and sitemap URLs. Brand variants are FocusTV, Focus TV and Focus TV Studios. Metadata uses the existing Australian film and media production positioning; the approved visible copy and page designs are preserved.

The main search topics are:

| Page                | Subject                                                            |
| ------------------- | ------------------------------------------------------------------ |
| Home                | FocusTV / Focus TV; Australian film and media production           |
| Production Services | Commercial film production, brand films and corporate storytelling |
| About               | FocusTV company and founder story                                  |
| Team                | Film production team and credits                                   |
| Gallery             | Interview and behind-the-scenes production photography             |
| Contact             | Film production, partnership and guest enquiries                   |

These topics guide metadata, not a promise of rankings. The broad term "focus" has many unrelated meanings and competitors.

## Structured data and social images

Server-rendered JSON-LD describes the Organization, WebSite, individual pages, breadcrumbs, commercial services and Gallery images. It uses the supplied logo and verified site details. No address, phone number, reviews, ratings, awards or unconfirmed partners are invented. There is no VideoObject markup because complete verified video-publication details are not available.

`src/app/opengraph-image.tsx` generates a 1200×630 branded social card using the existing mark and approved wording. It serves an image endpoint, not another website page. No duplicate photo or PNG asset is added to the public media library.

## Crawling and indexing

`/robots.txt` and `/sitemap.xml` are generated by Next.js. The sitemap lists only the six active pages and includes the Gallery image URLs. Query variants of Contact share its canonical URL. Retired AI URLs remain 404; legacy Cast and Contact redirects remain in the Next.js configuration.

Production is indexable by default. Vercel preview/development is not. Set `SITE_INDEXABLE=false` before building a non-production deployment on another host. Both robots.txt and page robots metadata use the same policy. Crawlers can access the HTML and image resources; large image previews and normal snippets are allowed on production.

## AI search

Google's AI search features use the same foundations: crawlable, indexable pages, helpful content and clear technical structure. There is no special Google AI schema or required AI text file. The site adds factual entity and page context without hidden keyword text or rewriting the approved copy. See [Google's AI search guidance](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide).

## Launch and ongoing work

1. Deploy to the final HTTPS domain and confirm canonicals, redirects, robots and sitemap in the live environment.
2. Verify a Google Search Console Domain property using Google's exact DNS TXT token. Submit `https://focustv.tv/sitemap.xml` and inspect the six canonical URLs. Verify Bing Webmaster Tools if used.
3. Test the live pages with Google's Rich Results Test and Schema Markup Validator. Review social previews after deployment.
4. If the business is eligible, claim or update its Google Business Profile using the real business details, accurate category and approved photographs. A map, reviews and business panel like the reference screenshot require account/business verification; code alone cannot create them.
5. Monitor indexing, search queries, leads and real-user Core Web Vitals. Request owner approval before changing copy, adding pages or making design changes. Confirm any business claims and credits before publishing new content.

Google chooses rankings, title/snippet presentation, sitelinks and rich-result eligibility. No code change guarantees first place, a knowledge panel or images in every result. [Google sitelinks guidance](https://developers.google.com/search/docs/appearance/sitelinks) and [Organization structured data](https://developers.google.com/search/docs/appearance/structured-data/organization) explain these controls.

## Performance and accessibility limits

The hero image receives high fetch priority. The unused serif font no longer competes for early preload bandwidth; the existing rendered fonts remain in place. The footer uses a sequential heading hierarchy with the same wording and styles. Further changes to approved colors, layout, animations or playback require owner approval.

Lighthouse is a local lab measurement, not a ranking or a live field-data result. Existing gold-text and footer contrast failures require changes to approved colors to clear; those colors are preserved under the owner's instruction. The mobile homepage also has JavaScript blocking time and layout work from the existing interactive experience. Changing approved animations or playback to pursue a score is outside this change.
